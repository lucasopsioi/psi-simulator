# FSD PSI 推演

渠道库存风险管理桌面工具（Electron 便携版 exe）。周度导入三类 PSI 底表（FSD 表 / 下游渠道表 / 音频专表），推演 SO/SI/ST 与各月末 DOS，支持监控对账、层层拍数与 Excel 交互。

## 结构与单一事实源

- `FSD-PSI.html` — 整个应用（CSS + 12 个页签 UI + CORE 逻辑块）。
  **所有解析与计算口径只存在于 `/*CORE-START*/ … /*CORE-END*/` 之间**；
  `main.js`（Electron 主进程读文件夹）与 `test.js`（回归测试）用同一正则抽取该块执行，零逻辑复制。
- `main.js` — 开窗、文件夹扫描（含 `scan-progress` 进度事件）、状态/数据文件持久化（userData，原子写 + 每日备份近 10 份）。
- `package.json` — `name: "fsd-psi-sim"` 是 userData 目录锚点，**永远不许改**，改了老用户数据全部失联。
- 发布纪律：`node test.js` 全绿 → `npx electron-builder` → 冻结 exe 跑 `--selftest-dir` 三文件夹真实规模自测，`_selftest_result.json` 里 `"ok":true` 才允许发布。**发布三站(2026-08-31 起)**:①复制到 `D:\workspace\发布\Acme包\FSD-PSI-Sim_VXX.exe`;②**复制到桌面 `C:\Users\demo\Desktop\FSD-PSI-Sim_VXX.exe`(用户一点即开,旧版 FSD-PSI-Sim_V*.exe 先删)**;③发手机——**2026-09-01 起用户拍板「每次做完发手机」，三站一次走完，不再等审图点头**（`py -3 scripts/send_to_phone.py`，MD5 对账一致才算送达；手机没连=报一句等用户，不轮询）。
  **⚠ 自测参数必须用等号形式** `--selftest-dir=<路径>`（`argOf` 只解析 `name=value`）；用空格形式传参会被静默忽略，应用按普通模式启动（隐藏窗口挂住、永不写结果 json，表现酷似"自测死锁"）。排查渲染进程要用 `--enable-logging`——Electron 33 起 `console-message` 事件签名变了，main.js 里旧的 RENDERER_ERR 转发已失效。
  自测/截图模式自动切到隔离 userData（`%TEMP%\fsd-psi-selftest-profile`，每次先清空）：冒烟拍数、演示剧本、夹具文件夹路径都不会写进真实用户方案（V27 后修复；此前本机 dev 方案里的夹具路径/演示数据即此来源）。
- **版本纪律（2026-08-26 起，当前 V10）**：每次发布版本号 +1。改两处——`FSD-PSI.html` head 里的 `window.APP_VER`（界面标题与启动页显示自动跟随，selftest 结果也带 version 字段）和 `package.json` 的 `version`（VXX 对应 XX.0.0）。复制到Acme包时文件名带版本：`FSD-PSI-Sim_VXX.exe`（旧版本文件删除，`scripts/send_to_phone.py` 自动取最新的 `FSD-PSI-Sim*.exe` 发送，手机端按前缀清旧包）。向用户汇报时必须报版本号。

## 已知边界（有意为之的设计取舍）

1. **Period 六位数字歧义**：`2026026` 按 ISO 周解析（2026 年第 26 周）。若底表出现 `YYYYMM` 月度口径的六位数（如 `202611`），会被读成周而产生错位——本工具只接周度底表，月度表不在支持范围。
2. **底表自带 ST 列会被忽略**：历史 ST 一律由 INV1 变动推导（上周 INV1 + 本周 SI − 本周 INV1，缺 INV1 周的 SI 会累计到下一个有 INV1 的周）。若未来底表新增 ST 列，导入不报错但不会采用该列，需在 CORE 增加对接。
3. **音频跳零口径**：音频与智能配件线 SO=0 视为未报量（跳过），其它产品线的 0 是真实零销。该口径贯穿 DOS 窗口、预测种子、季节系数、监控指标与 ST→SO 激活评估。
4. **推演汇总层级监控的口径**：聚合与推演汇总页一致（不含免推演/豁免/待确认项），因此「待确认」项完成确认后，同一层级的监控数值口径会随之变化，属预期行为。
5. **电渠标记**：ST→SO 激活效率按 电渠（ST 当周–次周）/ 线下（ST 后第 1–3 周铺货期）分窗口评估；未标记渠道一律按线下口径。关键词提示（Amazon/Mercado/Online 等）只是建议，以人工勾选为准。

## V18–V21 增量模块（国家 SO 目标闭环）

- **第四数据源**：国家 SO 目标回填表（`folder4`，宽表 21 列，`parseTargetGrid` 模糊表头识别，全角空格=未填）。口径已用样例行锁死：月底库存 = 上月底库存 − 该月目标；月底DOS = 月底库存 ÷ (该月目标/28)。
- **SO目标页双视图**：跟踪视图（承诺制评判：已结束月看 SO 达成与实际 DOS vs 承诺 DOS，进行中月看时间进度；年底按产品系族基线）+ 模板视图（原封列序可编辑，「导出模板 Excel(带公式)」出活公式表发国家）。
- **渠道属性**（`chanProp`）：线下/电渠/商城Eshop + 每渠道补货周期天数；Eshop 不参与 DOS 考核。**渠道类别**（`chanClass`）：真FSD/间接渠道 + 改名（间接渠道监控转下游口径、推演停用自动补货）。
- **大盘增速**（`bigGrowth`）：全局/产品线/产品系族三层倍数，作用于全部自动推演。
- **补货规律回测**：系数页一键回测（`replenishStats`），一次性铺货（≤2 次显著 SI 后 ≥tailWeeks 周静默仍动销）为警示模式。
- **周→月归属**：全局按该周周四所在月（`monthOfP`）。
- **未映射产品**：底表出现映射表外的产品 → 设置页红色警示面板，不静默放行；新品需人工补 `PRODUCT_MAP`。
- **改名迁移**：FSD 类别改名与下游渠道改名共用 `migrateNameExtras`（单元键 + 层系数键 + 渠道属性 + 汇总监控节点键）。

## V23–V24 增量（SI/SO 模拟引擎）

- **平销引擎**（`baselineOf`）：剔除 首销期(默认8周)/尾部衰退段(仅真衰退)/大促周(国家周历∪周系数>κ)/缺货周(双条件:低库存且低销) 后取中位数 + Theil-Sen 漂移(限 −3%~+1%/周)；置信 high≥10/mid≥6/low。FSD 逐产品「按平销推演」，下游/音频全局切换基准（低置信自动回退近4周均——**设计决策**：不做跨渠道借数外推，单元级 avg 兜底更稳）。系数页「平销体检」全量显性化。
- **国家大促周历**（17 国草案内置可编辑）+ **渠道大促节点**（跨年同期放量≥1.6×≥2年自动建议，人工确认/否决）。
- **产品生命周期**：末次SI(停购+几何衰减,ρ 从历史退市品学习)/退市周(残值水位×1.5 告警,退市不清零)/承接(接入新品规划,老品让出量×0.7)。系族默认周期 `FAM_LIFE_DEF`。
- **新品规划**：虚拟单元物理隔离；锚品渠道级平销×缩放(+承接量)、逐渠道首SI周可改、起量=手设>历史学习>类型默认、大促上市加成(α1.8/首批SI×1.3)、系族超容提醒、锚品重放校验、上市4周自动复盘(偏差>30%红提示)。汇总树 retail 源可叠加。
- **模型回测台**：holdout 滚动多窗口(含去年大促段)双模型 WMAPE 对比，切换纪律≥10%；Worker 并行+单线程兜底。
- **截图/诊断**：`--shot-dir`/`--shot-tabs`(支持 `tab@y` 分段)、`_panels.json` DOM 面板清单落盘。
- **已知边界**：在售品↔在售品承接不进主推演循环（承接仅作用于新品规划）；`learnReplenish` 不按渠道类型分箱（渠道自身历史已隐含其特征，学习值缺失时回落线默认）；Worker 在 file:// 下如失败自动单线程兜底（数据量下毫秒级，无感知）。

## V27 增量（产品总控 + 性能缓存）

- **性能缓存层**：`dataGen` 数据代号（10 处数据变更点 `bumpDataGen`）+ `calcCache()` 按代缓存 平销b̂/补货学习/季节系数层/促销周历/型号平销总量/爆发系数；实测 computeAll 冷 86ms → 热 15ms。手工拍数/锁量等推演参数变更不碰数据代,缓存持续命中。
- **「产品总控」页**（nav 第二位）：型号级操盘台,粒度=产品×型号（权威源=FSD直签全集剔除音频行+音频专表;下游表不并入总量防重复计数）。每型号一行：当前INV/DOS/近4周均SO/平销Σ(置信计数)/爆发系数(算得×改写)/未来SO/未来SI/锁量组件+状态 chips（已锁量/超发/分配≠总量/断供@周/停购/低置信/手工×N）。点行展开：调节条（型号增速>系族>线>全局、平销总量改写=各单元等比缩放、爆发系数改写）+ 型号分月 **SI/SO/月末INV/月末DOS 四行网格**（SI/SO 可拍,守恒分配）+ 分国家块（历史占比条+占比改写+锁量分配+每国同款四行网格,国家级拍数只分配到该国单元）。
- **锁量引擎**（`applyLockConstraints`）：`lockQty[产品||型号]={on,total,byC}`;已发=本年实际SI(权威源),余量=总量−已发;两层压缩——国家配额(填了才生效)→大区总余量,只压规则SI、**手工SI改写原样保留**;压缩后重跑模拟并开 `capSO`（SO≤期初库存+当周到货,超出即断供标记,断供周上卡片与行 chips 报警）。selftest 断言:压缩后 ΣfutSI=余量(精确)。
- **爆发系数** `C.burstOf`：近52周大促周均销÷平销周均销(首销期剔除,音频跳零),夹逼[1,10];改写后大促周推演= 平销×倍数(replaces 周系数,只在改写时生效)。
- **模型级拍数分配**：型号月度SO/SI 拍数按 国家权重(占比改写>近26周历史占比)→国内现值 两层守恒分配;国家级拍数按现值守恒分配;「恢复公式」按月按层清除。
- **导出**：总控宽表(型号行+国家行,含每月 SO/SI/INV/DOS);**销量推演长表**——列位与用户「月度SO实际数」页一致(F=产品线,I=产品型号,J=月份Excel序列,K=Measure,L=QTY),历史月=底表实际+未来月=推演,整表粘回其推演 Excel 后原 SUMIFS 直接取数(DOS 由其表内公式自算,28/35 天口径与周四归月天然一致)。
- selftest 新增 mkOk(总控渲染+展开断言)/lockOk(锁量压缩精确性)/perf(冷热计时);tests 323 项(burstOf 4 例+capSO 9 例)。

## V58（下游锁量的生命周期天花板 + 下游全链路 5 台取整）

- **用户（2026-09-02）**：①下游的 INV1 总量也受总锁量限制——锁量总量包含了下游渠道库存和 INV1；②下游所有模拟仍要取整到 5 台，不是 1 台。

## V66（拍数逻辑多代理审计：12 条确认缺陷 → 6 个根因全部修复）

- **用户（2026-09-02）**："你自己测一下拍数的逻辑，到底是不是正确的，看看有没有遗漏的。" 做法：给软件加**探针模式**（`main.js --probe-file=<js>` + `window.__probePrep`：载入夹具+全量推演后在页面上下文执行任意脚本，结果落盘；每个探针独立 userData 可并行），再用工作流让 5 个读图代理分段列不变量/疑点（97 条），22 条高危疑点各派代理在真实夹具上写探针验证，12 条完成且全部确认为缺陷（余下因会话额度中断）。探针脚本与原始数值在 scratchpad/probes。
- **根因 1 · 拍数处理读的是渲染时的旧快照**：`renderPivot` 的 `valMap`/`cellsOf` 用首次渲染的对象，拍数后只 `pv2Patch` 不重绘，于是连拍时清尾用拍前库存（探针：清尾写 1,148 而现值 1,923，期末库存 775 不归零）、层级拍数按拍前现值拆分（MPS 刚拍 0 却分到 290）、批量清尾后格无视前格已卖空。修：`valMap` 改为 `pv2Patch` 后回写新值；`cellsOf` 按单元键取重算后的新对象；批量里遇清尾先冲刷前面的拍数再算。
- **根因 2 · 三源同名单元共用覆盖层**：`ovSO/ovSI/ovExt` 键 = 国家::账户::型号，不含源。FSD 表音频行与音频专表同键（夹具自带）、V56 镜像行（间接表里的 Amazon）与 FSD 同键 → 下游/音频视图拍数静默改写 FSD 同名单元（反向亦然），锁量把对方的拍数当手拍 fixed 占预算并 manOver，明年段两行被写同一值。修：覆盖层按源前缀（FSD 裸键兼容旧方案，下游 `r|`、音频 `a|`；明年段 `r|/a|/n|`），读写两端 20 余处统一走 `ovKey/ovExtKeyOf`；启动时把旧方案里属于下游/音频单元的裸键迁到带源键（`ovMigrateSrc`）。
- **根因 3 · 承接比例取段内最后一周**：整桶拍数 5 台步长拆分后末周有取整噪声（公式值 3 拍成 5 → 后续所有月 ×1.67；拍高 220→225 反而让 11/12 月降 4.8%）。修：`C.carryTaps` 与 `budgetRowsOv` 都按「连续手拍段」合计 Σ拍值÷Σ公式值（只计公式值>0 的周），单周拍数退化为旧口径。
- **根因 4 · 拍 0 承接 0.2**：拍 0 把之后 14 个月全砍到 20%；当月输入小于已实际时无提示地弹回并砍后续。修：段合计为 0 不承接（只改本期，后续按公式）；当月桶拍值低于已发生实际 → 拒绝并提示「本桶已发生实际 N，最低只能拍 N」，不写覆盖层。**口径待拍板：拍 0 的含义是"只改本期"（现实现）还是"停售后续为 0"。**
- **根因 5 · FSD 今年段手拍 SO 超库存直接负库存**：`simulateUnit` 没有补足也没有硬约束，负库存/负 DOS 累进国家合计并把负 SO 带进明年。修：与下游/新品/明年段同口径——手拍 SO 高于可售且 SI 未手拍 → 当周进货补足（`siSrc='tapcover'`）；末次 SI 后不补、按可售压回并标 `capped`；任何周库存不为负（公式 SO 超库存同样压回）。下游 `simulateRetail` 末次 SI 后同样不再 tapcover。

## V70（粘贴外部表格 3.9 秒 → 54 毫秒；单格拍数 4 毫秒）

- **用户（2026-09-02）**："单次一定要更低，要和用普通 Excel 一样的体验；现在复制外面的表格数据进去也很慢。" 用 576 单元 × 87 周的合成底表量到：**粘贴 20 个格要 3.9 秒**，200 格 10.3 秒。
- **头号原因：被拒绝的输入会整页重绘。** 拍数链里「非数字 / 低于本桶已发生实际 / 该桶无可拍未来周 / 外推层无数据」四条拒绝分支都调用了 `render()`，在大表上一次 0.6–1.4 秒。粘贴外部表格时，很多格的值低于该月已发生的实际数，于是**每被拒绝一格就整页重绘一次**。现在拒绝只把那一格的文本还原并提示（Excel 行为），不再重绘；产品总控的三条同款分支一并改掉。单这一项：粘贴 20 格 3946ms → 64ms。
- **第二：批量里每遇父子行重叠就整体重算。** V68 为保证「批量结果 == 逐格结果」，在重叠时会把整批已写入的范围全部重算并原地更新（约 17ms/次，200 格里十几次）。现在改为只把「当前层级这些单元」重算到最新并刷新它们的桶值，不重建明年底表、不动 DOM；其余待处理的写入仍留到批结束一次性完成。语义不变（`batchDup` 门禁仍断言批量==逐格）。
- **第三：每粘一格都重建整张明年底表。** 外推层拍数每格都 `ovExtGen++`，使明年底表与外推映射整体失效。现在批量内攒着，批结束（或遇到重叠需要真重算时）再统一失效。
- 其余：批量写入改用元素引用而非每格一次 `document.querySelector`；撤销栈合并由 `concat` 改 `push`（几百格时 `concat` 是平方级）；延伸段整表在少量单元变化且行数不变时复用上次数组、只替换变化的那几段。

| 动作 | 优化前 | 现在 |
|---|---|---|
| 单格拍数（叶子） | 302ms → 4ms（V69） | **4ms** |
| 单格拍数（产品层） | 12ms（V69） | **11ms** |
| 粘贴 20 格 | 3946ms | **54ms** |
| 粘贴 200 格 | 10332ms | **455ms** |
| 粘贴 480 格 | 11976ms | **640ms** |

- 诊断留存：拍数链内置分段计时（`window.__tapProf`，可选 `window.__tapProfAgg` 累加），以后排查性能不用再改代码。

### V72 同版修复：明年列出现非 5 倍数（用户 2026-09-04 截图发现）

- **现象**：推演编辑明年列，型号行 SO 出现 19 / 13 / 169 / 187 这类不是 5 的倍数的数，而同一行前几个月你手拍的 60/75/25 都是 5 的倍数。
- **根因**：明年某月拍数后，其后未拍月按「Σ拍值 ÷ Σ公式值」的比例承接。这个比例乘出来是小数，两处代码都只 `Math.round` 取到 **1 台**（`budgetRowsOv` 承接月、`buildBudgetRows` 延伸段承接月）。随后按周守恒拆分时，总量 19 无法拆成若干个 5，余数只能塞进某一周，月合计就定死在 19。
- **复现**：基表月值 25、承接比例 0.77 → 旧口径 `Math.round(19.25)=19`，`distribute(19,step5)` 得到 `5,9,5,0`；新口径 `round5(19.25,5)=20`，得到 `5,5,5,5`。
- **修**：两处都改成先 `F.round5(…,roundTo)` 取到步长再拆分。
- **门禁 `roundStepOk`**：明年拍一个刻意非步长的值逼出承接段，断言所有承接月（备注含「承接拍数比例」）的 SO 与 SI 都是步长倍数。实测 11 个承接行全部合规。此前夹具里没有明年手拍，承接路径从未被门禁走过。
- **仍会出现非 5 倍数的一处**：库存不够时 SO 被压到「最多只能卖这么多」。那是约束结果不是推演值，是否也向下取整到 5 台待拍板。

### V72 门禁基建修复

## V73（待确认：从一堆散项变成按原因分组 + 一个开关）

- **用户（2026-09-04）**：「不确定的数据太多，真的太多了。每次一看有很多需要我确认的，我都头很大。我不知道原因在哪。」
- **根因**：`C.classify` 只看「去年同期够不够参考」——去年该单元有销量的周 ≥`minHistWeeks`(8) **且** 未来周的去年同期覆盖率 ≥`minRefCov`(60%)。**完全不看今年自己够不够推**。判定粒度是 国家×账户×型号，所以今年新上的型号、今年新开或改过名的渠道，去年这个组合根本不存在，一律判 `new`——哪怕今年已经卖了半年。更要紧的是：待确认单元 `sim.blocked=true`，**今年剩余周 SO 直接推成 0**，所以待确认多不只是烦，它让总量偏低。而平销引擎 `bl` 用的是**今年自身**数据（有效周 ≥6 为 mid，≥10 为 high），这些单元本来就能自动推。
- **待确认页重做**：顶部四张 KPI（待确认合计 / 今年数据够可直接按平销 / 今年也没足够销量 / 免推演），中间一段说清判定规则与「会被推成 0」的后果；然后按三组折叠——**今年新型号**（去年整表这个型号一周都没有）、**新渠道或渠道改过名**（去年有同型号但不在这个渠道）、**去年数据断续**（该单元去年有数但没到门槛）。每组两个按钮：「按平销确认（N 项）」只作用于今年数据够的；「其余按近4周均确认（N 项）」处理剩下的。展开后是一张表，逐单元列出 去年周数 / 同期覆盖 / 当前INV / 近4周均SO / **今年有效周 / 平销 b̂ / 置信度**，以及单项四个按钮（平销 / 近4周均 / 按自身去年 / 停售）。锚定别的型号仍在推演明细页，点行即到。

- **门禁 `pendGroupOk`**：把自动判定门槛临时拉满，强行造出一批待确认单元（实测 288 项），断言 ①分组不重不漏 ②开关打开后可平销的那些全部退出待确认 ③它们今年剩余周不再被推成 0 ④关掉后完全还原。

### V73 门禁修复：原生弹框冻结渲染进程

- **现象**：自检在不同版本卡在不同位置（`xgPvOk` / `expLong` / `udOk`），日志停在最后一步毫无线索，外部超时前一直静默，白跑了几轮 25 分钟。
- **真因**：导出成功后会 `alert('…已导出')`。`alert/confirm/prompt` 是**同步阻塞**的——一旦弹出，渲染进程的事件循环整个冻结：定时器不再触发、IPC 回包收不到、`console` 也送不出去，而主进程一切正常，只能干等。此前只在基线采集期间桩掉了弹框，采集结束就还原，后面的导出门禁一碰就死。卡在哪一步，取决于哪个门禁先碰到弹框，所以看起来「每次不一样」。
- **修**：自检开头一次性桩掉三个弹框并记录谁弹过（`tms.dlgCalls`），全程不还原。修完自检从「卡死 25 分钟」变成 **6 秒跑完**。
- **配套**：主进程加心跳（`MAIN_ALIVE`，用来区分主进程被堵还是渲染进程被堵）、`render-process-gone` 捕获、20 分钟看门狗（超时写失败结果并退出，不再静默）；日志每行带累计秒数；自检内所有 IPC 加 20 秒竞速超时。
- **顺带**：`expLong`（四年跨度长表诊断，2026-09-02 的 bug 早已修复）是整个自检最重的一块，改为 `opts.expLong` 按需开启，不参与任何断言。
