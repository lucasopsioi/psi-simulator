# FSD PSI 推演

渠道库存风险管理桌面工具（Electron 便携版 exe）。周度导入三类 PSI 底表（FSD 表 / 下游渠道表 / 音频专表），推演 SO/SI/ST 与各月末 DOS，支持监控对账、层层拍数与 Excel 交互。

## 结构与单一事实源

- `FSD-PSI.html` — 整个应用（CSS + 12 个页签 UI + CORE 逻辑块）。
  **所有解析与计算口径只存在于 `/*CORE-START*/ … /*CORE-END*/` 之间**；
  `main.js`（Electron 主进程读文件夹）与 `test.js`（回归测试）用同一正则抽取该块执行，零逻辑复制。
- `main.js` — 开窗、文件夹扫描（含 `scan-progress` 进度事件）、状态/数据文件持久化（userData，原子写 + 每日备份近 10 份）。
- `package.json` — `name: "fsd-psi-sim"` 是 userData 目录锚点，**永远不许改**，改了老用户数据全部失联。
- 发布纪律：`node test.js` 全绿 → `npx electron-builder` → 冻结 exe 跑 `--selftest-dir` 三文件夹真实规模自测，`_selftest_result.json` 里 `"ok":true` 才允许发布。**发布三站(2026-08-31 起)**:①复制到 `D:\workspace\发布\Acme包\FSD-PSI-Sim_VXX.exe`;②**复制到桌面 `C:\Users\demo\Desktop\FSD-PSI-Sim_VXX.exe`(用户一点即开,旧版 FSD-PSI-Sim_V*.exe 先删)**;③发手机——**2026-09-01 起用户拍板「每次做完发手机」，三站一次走完，不再等审图点头**（`py -3 scripts/send_to_phone.py`，MD5 对账一致才算送达；手机没连=报一句等用户，不轮询）。
  **⚠ 自测参数必须用等号形式** `--selftest-dir=<路径>`（`argOf` 只解析 `name=value`）；用空格形式传参会被静默忽略，应用按普通模式启动（隐藏窗口挂住、永不写结果 json，表现酷似"自测死锁"）。排查渲染进程要用 `--enable-logging`——Electron 33 起 `console-message` 事件签名变了，main.js 里旧的 RENDERER_ERR 转发已失效。
  自测/截图模式自动切到隔离 userData（`%TEMP%\fsd-psi-selftest-profile`，每次先清空）：冒烟拍数、演示剧本、夹具文件夹路径都不会写进真实用户方案（V27 后修复；此前本机 dev 方案里的夹具路径/演示数据即此来源）。
- **版本纪律（2026-08-26 起，当前 V10）**：每次发布版本号 +1。改两处——`FSD-PSI.html` head 里的 `window.APP_VER`（界面标题与启动页显示自动跟随，selftest 结果也带 version 字段）和 `package.json` 的 `version`（VXX 对应 XX.0.0）。复制到Acme包时文件名带版本：`FSD-PSI-Sim_VXX.exe`（旧版本文件删除，`scripts/send_to_phone.py` 自动取最新的 `FSD-PSI-Sim*.exe` 发送，手机端按前缀清旧包）。向用户汇报时必须报版本号。

## 已知边界（有意为之的设计取舍）

1. **Period 六位数字歧义**：`2026026` 按 ISO 周解析（2026 年第 26 周）。若底表出现 `YYYYMM` 月度口径的六位数（如 `202611`），会被读成周而产生错位——本工具只接周度底表，月度表不在支持范围。
2. **底表自带 ST 列会被忽略**：历史 ST 一律由 INV1 变动推导（上周 INV1 + 本周 SI − 本周 INV1，缺 INV1 周的 SI 会累计到下一个有 INV1 的周）。若未来底表新增 ST 列，导入不报错但不会采用该列，需在 CORE 增加对接。
3. **音频跳零口径**：音频与智能配件线 SO=0 视为未报量（跳过），其它产品线的 0 是真实零销。该口径贯穿 DOS 窗口、预测种子、季节系数、监控指标与 ST→SO 激活评估。
4. **推演汇总层级监控的口径**：聚合与推演汇总页一致（不含免推演/豁免/待确认项），因此「待确认」项完成确认后，同一层级的监控数值口径会随之变化，属预期行为。
5. **电渠标记**：ST→SO 激活效率按 电渠（ST 当周–次周）/ 线下（ST 后第 1–3 周铺货期）分窗口评估；未标记渠道一律按线下口径。关键词提示（Amazon/Mercado/Online 等）只是建议，以人工勾选为准。

## V18–V21 增量模块（国家 SO 目标闭环）

- **第四数据源**：国家 SO 目标回填表（`folder4`，宽表 21 列，`parseTargetGrid` 模糊表头识别，全角空格=未填）。口径已用样例行锁死：月底库存 = 上月底库存 − 该月目标；月底DOS = 月底库存 ÷ (该月目标/28)。
- **SO目标页双视图**：跟踪视图（承诺制评判：已结束月看 SO 达成与实际 DOS vs 承诺 DOS，进行中月看时间进度；年底按产品系族基线）+ 模板视图（原封列序可编辑，「导出模板 Excel(带公式)」出活公式表发国家）。
- **渠道属性**（`chanProp`）：线下/电渠/商城Eshop + 每渠道补货周期天数；Eshop 不参与 DOS 考核。**渠道类别**（`chanClass`）：真FSD/间接渠道 + 改名（间接渠道监控转下游口径、推演停用自动补货）。
- **大盘增速**（`bigGrowth`）：全局/产品线/产品系族三层倍数，作用于全部自动推演。
- **补货规律回测**：系数页一键回测（`replenishStats`），一次性铺货（≤2 次显著 SI 后 ≥tailWeeks 周静默仍动销）为警示模式。
- **周→月归属**：全局按该周周四所在月（`monthOfP`）。
- **未映射产品**：底表出现映射表外的产品 → 设置页红色警示面板，不静默放行；新品需人工补 `PRODUCT_MAP`。
- **改名迁移**：FSD 类别改名与下游渠道改名共用 `migrateNameExtras`（单元键 + 层系数键 + 渠道属性 + 汇总监控节点键）。

## V23–V24 增量（SI/SO 模拟引擎）

- **平销引擎**（`baselineOf`）：剔除 首销期(默认8周)/尾部衰退段(仅真衰退)/大促周(国家周历∪周系数>κ)/缺货周(双条件:低库存且低销) 后取中位数 + Theil-Sen 漂移(限 −3%~+1%/周)；置信 high≥10/mid≥6/low。FSD 逐产品「按平销推演」，下游/音频全局切换基准（低置信自动回退近4周均——**设计决策**：不做跨渠道借数外推，单元级 avg 兜底更稳）。系数页「平销体检」全量显性化。
- **国家大促周历**（17 国草案内置可编辑）+ **渠道大促节点**（跨年同期放量≥1.6×≥2年自动建议，人工确认/否决）。
- **产品生命周期**：末次SI(停购+几何衰减,ρ 从历史退市品学习)/退市周(残值水位×1.5 告警,退市不清零)/承接(接入新品规划,老品让出量×0.7)。系族默认周期 `FAM_LIFE_DEF`。
- **新品规划**：虚拟单元物理隔离；锚品渠道级平销×缩放(+承接量)、逐渠道首SI周可改、起量=手设>历史学习>类型默认、大促上市加成(α1.8/首批SI×1.3)、系族超容提醒、锚品重放校验、上市4周自动复盘(偏差>30%红提示)。汇总树 retail 源可叠加。
- **模型回测台**：holdout 滚动多窗口(含去年大促段)双模型 WMAPE 对比，切换纪律≥10%；Worker 并行+单线程兜底。
- **截图/诊断**：`--shot-dir`/`--shot-tabs`(支持 `tab@y` 分段)、`_panels.json` DOM 面板清单落盘。
- **已知边界**：在售品↔在售品承接不进主推演循环（承接仅作用于新品规划）；`learnReplenish` 不按渠道类型分箱（渠道自身历史已隐含其特征，学习值缺失时回落线默认）；Worker 在 file:// 下如失败自动单线程兜底（数据量下毫秒级，无感知）。

## V27 增量（产品总控 + 性能缓存）

- **性能缓存层**：`dataGen` 数据代号（10 处数据变更点 `bumpDataGen`）+ `calcCache()` 按代缓存 平销b̂/补货学习/季节系数层/促销周历/型号平销总量/爆发系数；实测 computeAll 冷 86ms → 热 15ms。手工拍数/锁量等推演参数变更不碰数据代,缓存持续命中。
- **「产品总控」页**（nav 第二位）：型号级操盘台,粒度=产品×型号（权威源=FSD直签全集剔除音频行+音频专表;下游表不并入总量防重复计数）。每型号一行：当前INV/DOS/近4周均SO/平销Σ(置信计数)/爆发系数(算得×改写)/未来SO/未来SI/锁量组件+状态 chips（已锁量/超发/分配≠总量/断供@周/停购/低置信/手工×N）。点行展开：调节条（型号增速>系族>线>全局、平销总量改写=各单元等比缩放、爆发系数改写）+ 型号分月 **SI/SO/月末INV/月末DOS 四行网格**（SI/SO 可拍,守恒分配）+ 分国家块（历史占比条+占比改写+锁量分配+每国同款四行网格,国家级拍数只分配到该国单元）。
- **锁量引擎**（`applyLockConstraints`）：`lockQty[产品||型号]={on,total,byC}`;已发=本年实际SI(权威源),余量=总量−已发;两层压缩——国家配额(填了才生效)→地区部总余量,只压规则SI、**手工SI改写原样保留**;压缩后重跑模拟并开 `capSO`（SO≤期初库存+当周到货,超出即断供标记,断供周上卡片与行 chips 报警）。selftest 断言:压缩后 ΣfutSI=余量(精确)。
- **爆发系数** `C.burstOf`：近52周大促周均销÷平销周均销(首销期剔除,音频跳零),夹逼[1,10];改写后大促周推演= 平销×倍数(replaces 周系数,只在改写时生效)。
- **模型级拍数分配**：型号月度SO/SI 拍数按 国家权重(占比改写>近26周历史占比)→国内现值 两层守恒分配;国家级拍数按现值守恒分配;「恢复公式」按月按层清除。
- **导出**：总控宽表(型号行+国家行,含每月 SO/SI/INV/DOS);**销量推演长表**——列位与用户「月度SO实际数」页一致(F=产品线,I=产品型号,J=月份Excel序列,K=Measure,L=QTY),历史月=底表实际+未来月=推演,整表粘回其推演 Excel 后原 SUMIFS 直接取数(DOS 由其表内公式自算,28/35 天口径与周四归月天然一致)。
- selftest 新增 mkOk(总控渲染+展开断言)/lockOk(锁量压缩精确性)/perf(冷热计时);tests 323 项(burstOf 4 例+capSO 9 例)。

## V57（下游手拍 SO 不被库存压回 + 锁量贯通下游的可见性与型号匹配容错）

- **用户（2026-09-02）**：推演编辑下游源只展开到产品时，①产品已锁量但未来仍有源源不断的 Purchase；②拍某月 SO 3000，瞬间变成 2997。
- **2997 根因**：产品层拍数按最大余数法拆到 渠道×型号×周 是守恒的，但 `simulateRetail` 有库存硬约束 `SO ≤ 期初库存+当周进货`，个别单元×周分到的 SO 超过可售就被压掉几台。修法与新品一致：**手拍 SO 高于可售时，当周 Purchase 补足差额**（`buySrc='tapcover'`）；SI 也手拍时不补（用户自己负责）；锁量重跑时全周 SI 为给定值，超出即 `capped` 标记。

- **型号匹配容错**：锁量对下游单元与延伸段行的匹配改为规整后比较（去首尾空格、忽略大小写；`mkEq`/`mkNorm`）。
- **下游预算含 INV1 可关**（工具条勾选，`state.cfg.lockRetailInv1`，默认开）：开=下游可进货预算 = 上游直接渠道自有库存 INV1 + 锁量余量（下游从分销商库存拿货，锁完后 Purchase 会继续直到分销商库存用完——这就是"锁了还有 Purchase"的物理原因）；关=只按锁量余量封顶，锁完即停。

## V58（下游锁量的生命周期天花板 + 下游全链路 5 台取整）

- **用户（2026-09-02）**：①下游的 INV1 总量也受总锁量限制——锁量总量包含了下游渠道库存和 INV1；②下游所有模拟仍要取整到 5 台，不是 1 台。
- **守恒天花板**：锁量总量是全生命周期天花板，所有已发的货此刻要么已卖给消费者、要么在下游库存、要么在 INV1。所以下游未来还能进的量 = **min(INV1 + 余量, 锁量总量 − 下游生命周期累计 Purchase)**（`C.retailLockBudget`，纯函数）。数据自洽时两项相等（因为 已发 − 下游累计 = INV1）；INV1 偏大（含锁量外库存或数据窗口外的历史）时由天花板兜住，保证 下游累计 + 未来 ≤ 锁量总量。填了国家配额的国家层同样取 min(该国 INV1+余量, 配额 − 该国下游累计)。明年延伸段预算 = 该天花板 − 今年已排。下游生命周期累计 Purchase（`retailLifePurchaseOf`）= 同型号全部下游单元历史 Purchase>0 跨年累计，不含音频、不含直达镜像行。推演编辑下游源的诊断行把 min 的两项都写出来。

## V60（数据准确性审计一：月末DOS 全软件统一按该月实际天数）
